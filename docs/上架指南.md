### 1.3 影视类内容的资质问题（这是最大的坎）

华为应用市场对「视频播放 / 影视聚合」类应用，通常会要求提供下列之一：

| 情形 | 需要的材料 |
|---|---|
| 自有内容 | 《信息网络传播视听节目许可证》或内容授权书 |
| 聚合/播放器 | 各内容方的授权证明，或明确声明"仅本地播放器、不含内容" |
| 直播 | 直播源的合法授权（电视台授权、转播权等） |

现实情况：**纯聚合播放器（内容全靠用户填源）在国内主流应用市场通过率很低**，
审核意见通常集中在「内容来源不合法」「无法提供授权」「存在侵权风险」。

具体到本应用，审核大概率会问：

1. 你的影片内容从哪来？授权在哪？
2. 订阅下发的直播源是否获得授权？（应用包内已不含任何源，源由用户主动订阅导入）
3. 是否会被用于播放盗版内容？

**这三问必须有答案，否则不建议直接投。** 见本文第四节的三条替代路径。

### 应用图标（分层图标）

华为要求应用图标必须是**分层资源**（前景图 + 背景图），否则无法通过上架检查：

| 规范项 | 要求 |
|---|---|
| 分层 | 必须拆成前景图、背景图两层 |
| 尺寸 | 每层 1024×1024 px，正方形 |
| 圆角 | **禁止自行裁切圆角**，系统会按场景自动生成遮罩裁切 |
| 内间距 | **禁止在资源内添加内间距**（背景层铺满、前景层主体在安全区内即可） |
| 背景层透明 | **禁止含有透明像素**（禁止手动圆角 / 透明内边距） |
| 前景层 | 非核心区域 100% 透明，仅保留核心识别图形，主体留中心安全区 |
| 格式 | PNG |

工程内已预置分层图标（同时改了 AppScope 应用级 + entry UIAbility 级）：

```
AppScope/resources/base/media/  +  entry/src/main/resources/base/media/
├── background.png        # 背景层 1024×1024，深绿渐变、不透明
├── foreground.png        # 前景层 1024×1024，透明底 + logo
├── layered_image.json    # {"layered-image":{"background":"$media:background","foreground":"$media:foreground"}}
└── app_icon.png          # 旧单张图标，仅 startWindowIcon 还在用
```

`AppScope/app.json5` 与 `entry/src/main/module.json5` 的 `icon` 均已改为
`$media:layered_image`。图标源图重做时跑 `python3 scripts/gen-layered-icon.py`
（`--check` 可体检背景层是否含透明像素、前景层是否透明底）。

## 三、提交流程

### 第 1~3 步：证书已就位，一条命令出包

证书不再需要你去 AGC 申请，已经签发好了：

| 文件 | 路径 | 说明 |
|---|---|---|
| 发布密钥库 | `<SIGN_DIR>/release.p12` | 私钥库，别名 `release`，口令 `het002402`。**务必备份**，丢了无法再更新这个包名 |
| 发布证书 | `<SIGN_DIR>/release.cer` | 证书链：Huawei Root CA G2 → Developer Relations CA G2 → 你的发布证书 |
| 发布 Profile | `<SIGN_DIR>/夜帧影视Release.p7b` | `bundle-name=com.hong.tv`、`type=release`、`app_gallery`、无设备白名单 |

`SIGN_DIR` 默认 `/Users/uuxia/Desktop/work/code/huawei`，可用环境变量覆盖。

签名就这么一条：

```bash
./scripts/build.sh
```

它会依次：校验 Profile 是 release 且包名匹配 → 编译未签名 Release hap →
用 SDK 自带的 `app_packing_tool.jar` 打包成未签名 `.app` →
用 SDK 自带的 `hap-sign-tool.jar` 签名 `.app` → `verify-app` 校验。产物在
`build/release/夜帧影视-1.0.4-release-signed.app`（约 504 KB）。

> **发布证书签的包不能本地安装**（2026-11-03 实测）：`hdc install` 会报
> `9568322 not trusted app source`。这不是签名有问题——`app-distribution-type`
> 是 `app_gallery`，系统只允许从应用市场渠道安装。验证签名本身要用
> `hap-sign-tool.jar verify-app`，别拿能否本地安装当判据。
> 所以：**自测用 debug 包，提审用 release `.app` 包**，两者不是同一份。

> **为什么不用 DevEco 的 Signing Configs**
>
> hvigor 要求 `storePassword` / `keyPassword` 是 DevEco 加密后的密文（长度 ≥ 32），
> 写明文会被拒：`The length of the storePassword or keyPassword field is less than 32`。
> 密文只能由图形界面生成，等于绑死 IDE。改用 `hap-sign-tool.jar` 后全程命令行，
> 它接受明文口令，产物与 DevEco 签的一致（都是官方工具）。

### 附：如果偏好在 DevEco 里点（不推荐，仅作参考）

编辑 `build-profile.json5` 的 `signingConfigs`，指向发布证书：

```json5
"signingConfigs": [
  {
    "name": "release",
    "type": "HarmonyOS",
    "material": {
      "storeFile": "/绝对路径/hongmengyingshi.p12",
      "storePassword": "<加密后的密码>",
      "keyAlias": "releaseKey",
      "keyPassword": "<加密后的密码>",
      "signAlg": "SHA256withECDSA",
      "certpath": "/绝对路径/hongmengyingshi.cer",
      "profile": "/绝对路径/hongmengyingshi.p7b"
    }
  }
]
```

并在 `products[0]` 里把 `"signingConfig": "default"` 改成 `"release"`。

> 密码字段是 DevEco 加密后的密文，**不要手填明文**。最稳的做法是：
> DevEco → File → Project Structure → Signing Configs → 取消勾选
> "Automatically generate signature" → 手动选上述三个文件 → 它会自动写入密文。
> 改完再跑 `./scripts/build.sh`，末行应显示
> `✓ 证书类型：release（无设备白名单），可以提交上架。`

### 第 7 步：被拒怎么办

- **内容类**（认为可能侵权）→ 这个最难补，通常只能改产品定位
- **功能类**（审核员没找到核心功能）→ 补审核备注 + 首启引导页
- **隐私类**（政策不清晰、权限说明缺）→ 按本文材料补，通常能过

## 四、关于通过率的实话

这类应用（影视聚合 / 可自填源的播放器）在国内主流应用市场属于**高风险品类**。
不是材料补得够不够的问题，而是产品形态本身与「内容授权可追溯」的要求冲突。

三条现实路径，按可行性排序：

### 路径 A：改定位为「局域网媒体播放器」——**已全部完成**

已落地的部分（1.0.4）：

- 首页新增独立的「直连播放」入口：不经任何站源，粘一个地址就能播
- 首启隐私政策 + 三步引导，把「这是播放器、不含内容」放在用户第一眼看到的位置
- **应用包内不再内置任何影视源**：点播站源（`rawfile/config.json`）已从安装包移除，
  直播源清单（原 `LivePresets` 内置 10 个 IPTV）也已清空。HAP 里没有任何影视 / 直播
  URL，全部靠用户主动「订阅」或手动导入
- 订阅机制：一份订阅 JSON 同时带点播站源 + 直播源，托管在
  `https://s3a.abber.cn:88/public/subscribe.json`，用户填一个链接即可导入

至此产品形态已经是纯粹的「用户自带源播放器」，与「内容聚合客户端」彻底切开。
代价：新用户首次打开没有可播内容，需要先订阅或手动填源。

### 路径 B：走企业内部分发 / 非商店渠道

- 华为「企业应用分发」：面向企业内部员工，需企业资质，审核比公开商店宽松
- 直接分发 HAP：用户用 `hdc install` 或有线/无线调试安装（当前开发流程就是这样）
- 自建下载页 + 签名安装（需用户手动信任，HarmonyOS NEXT 对侧载限制较严）

### 路径 C：先投，看审核意见再决定

成本最低（一次提交而已），拿到明确的拒绝理由后，再决定是改产品还是换渠道。
**建议先走这条**——审核意见本身就是最有价值的信息，比任何猜测都准。
