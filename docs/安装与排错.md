### 无线调试会话很短

`hdc tconn` 建好连接后，隔**一次** shell 调用就会失效，报
`Not match target founded, check connect-key please`。所以设备操作统一走 `scripts/hdcx.sh`，
它在同一条命令里完成 `kill → start → tconn → 执行`：

```bash
./scripts/hdcx.sh shell "bm get -u"                # 读 UDID
./scripts/hdcx.sh shell "param get const.product.model"
./scripts/hdcx.sh install -r entry/build/default/outputs/default/entry-default-signed.hap
```

会话仍在时不会重复 kill，避免打断 DevEco 自己的连接。

## 二、为什么包名是 `com.hong.tv`

本工程原本叫 `com.fanren.boxtv`，但复用了 ZspaceTV 那套现成签名后必须改名，原因是
`.p7b` 里的 bundle-name 是**硬绑定**的，hvigor 签名阶段就会拦：

```
00303074 Configuration Error
The bundleName in app.json5/hvigorfile.ts does not match
the bundleName in the generated SigningConfigs.
```

绕不过去的三个方向都试过、都失败：

| 尝试 | 结果 |
|---|---|
| 改 `.p7b` 里的 bundle-name | 那是华为签名的 PKCS#7，改一字节验签即失败 |
| 手搓 `hap-sign-tool` 跳过 hvigor 校验 | 设备端装包时仍按 profile 的 bundle-name 比对 |
| 脚本驱动 IDE 点「自动签名」 | AppleScript 发键击被系统拒（`-10004`，无辅助功能授权） |

所以改包名复用签名。当时电视上 `com.hong.tv` 已经没人占用
（极空间播放器已卸载，改用了官方 `com.zentraedi.zspacehm`），所以直接沿用。
电视桌面显示的名字是 **夜帧影视**（label 来自 `string.json`，与包名无关）。

要改回独立包名，就得在 DevEco 里重新走一次自动签名，然后把 `AppScope/app.json5`、
`scripts/install.sh` 里的包名一起换回去。

## 三、灵犀遥控器适配（重要）

华为智慧屏 的**灵犀遥控器**在系统里是**指针设备**，不是普通按键遥控器：

| 现象 | 原因 |
|---|---|
| `onKeyEvent` 一次都不触发 | 遥控器被识别为鼠标/指针，方向键是"移动光标"，不产生 DPAD 按键事件 |
| `onClick` 正常触发 | 确定键 = 鼠标左键点击，走的是点击事件 |
| 用 `hilog` 只能看到点击，看不到 key | 同上 |

实测日志（`hilog | grep BOXN`）：

```
root FOCUS            ← 焦点确实在根节点上
requestFocus ok       ← 抢焦点也成功了
center hit            ← 但只有点击，没有 key=
（全程没有一条 key= 日志）
```

**所以整个 App 的交互必须按「光标 + 点击」设计，不能依赖焦点和方向键。**

落地做法：

1. **焦点守卫**：根节点 `id('playerRoot')` + `onPageShow` 里 `requestFocus`，
   `onBlur` 后 200ms 再抢回来。焦点丢了按键通道就彻底丢了。
2. **悬停高亮**：所有可点元素加 `onHover`（复用 `focusKey` 状态），
   光标移上去就有蓝框——指针模式没有焦点框，这是唯一的位置反馈。
3. **可点击的控制按钮**：播放页底部控制条做成一排按钮
   （上一集 / −10 秒 / 暂停 / +10 秒 / 音量− / 音量+ / 下一集 / 静音），
   全部 `onClick`，不依赖按键。
4. **指针一动就唤出控制条**：`onMouse` 收到 `MouseAction.Move` 且 OSD 隐藏时调 `popOsd()`，
   否则用户不知道能点哪。
5. **进度条可点定位**：进度条容器 `onAreaChange` 记宽度，`onClick` 用 `ev.x / barW` 换算跳转比例。
6. **不用 emoji 做图标**：⏪ ⏯ 🔉 这些在鸿蒙上渲染成彩色方块，全部换成文字。
7. **热区要盖到整格，别只盖住文字**：直播频道格子（`GridItem` ≈ 110vp 高）里那个
   `Text` 只有 58vp，`onClick` 挂在 `Text` 上时，点格子上下那圈空白完全没反应；
   指针遥控对不准文字就表现为「点了没反应」。`onClick` 一律挂到 `GridItem` / 整行容器上。

### 指针遥控专用：ForEach 的 key 里绝不能放悬停态

这是「**指着某个台点下去毫无反应**」的真正根因，踩过一次：

```typescript
// ✗ 错误：key 里带了悬停态
(ch: Channel) => 'ch' + ch.name + (this.hi('ch_' + ch.name) ? 'h' : '')
```

ArkUI 的 `ForEach` 只按 key 决定要不要重建。指针一悬停 → `hoverKey` 变 → key 变 →
格子重建 → 新节点又触发悬停 → 再重建……`hilog` 实测**静置时每秒重建 6 次**，
按下去的那一下永远落在已经被销毁的节点上，所以点击事件收不到。

```typescript
// ✓ 正确：key 里只放数据态（是否失效 / 是否当前台）
(ch: Channel) => 'ch' + ch.name + ch.url +
  (this.isDead(ch.url) ? 'd' : 'a') + (this.isCur(ch) ? 'c' : '')
```

悬停高亮本来就走 `.backgroundColor(this.hi(...))` 的属性级状态绑定，不需要重建也会刷新。
同类问题检查方式：`hilog` 里同一个元素连续打印悬停日志、频率远高于指针移动速度，就是这个坑。

### 点击双通道去重

灵犀遥控的点击可能**同时**触发 `onClick` 和 `onMouse`（前者是点击事件，后者是鼠标按键）。
两个都挂时，动作入口必须去重，否则会 `pushUrl` 两次、叠出两层播放页：

```typescript
.onClick(() => this.tapChannel(ch))                       // 触屏 / 键盘确定
.onMouse(Pointer.pressRelease('ch:' + ch.name, () => {    // 指针遥控
  this.tapChannel(ch);
}))

// tapChannel 内部用 400ms 时间窗去重
if (!Pointer.once('ch:' + ch.name + ch.url)) { return; }
```

`Pointer.pressRelease()` 还要求「按下 + 抬起都在本元素上」才算一次点击，
否则指针划过列表再松手会被误判成点击。

> 顺带一个坑：`ClickEvent` **没有** `stopPropagation()`，编译直接报
> `Property 'stopPropagation' does not exist on type 'ClickEvent'`。
> ArkUI 的点击事件本来就不冒泡到父组件，直接去掉即可。

### 退出直播后还在出声（播放器泄漏）

「从直播页返回列表 / 按 Home 回桌面，声音还在响」在这个项目上是**四个独立漏洞叠加**，
修的时候要一起补，只补一个还是会漏：

| 漏洞 | 原因 | 修法 |
|---|---|---|
| ① `pause` 对直播不可靠 | `pausePlayback()` 带 `this.playing` 守卫，缓冲/换档中 `playing` 可能为 false，判断一挡就跳过；即便执行，部分 HLS 直播只会停止拉流，已解码的音频仍会放完缓冲 | 直播在 `onPageHide` 里**直接 `releasePlayer()`**，回来走重连；`pause` 去掉 `playing` 守卫 |
| ② 解析期间退出 | `aboutToAppear` 是 async：`await resolveUrl()`（直播要逐个探源，可能好几秒）期间用户按返回，页面先销毁，`await` 回来后又照样 `initPlayer()` —— 页面已没了，没人释放 | 加 `closed` 标志，`await` 之后必须检查 |
| ③ `createAVPlayer` 期间退出 | `await media.createAVPlayer()` 期间页面销毁，`aboutToDisappear` 时 `this.player` 还是 null，等 await 回来才赋值 → 实例永久泄漏 | `await` 之后再查一次 `closed`，已关闭就 `p.release()` 并返回 |
| ④ TV 按 Home | 部分电视系统只走 `Ability.onBackground`，页面 `onPageHide` 来得晚甚至不来 | 新增 `common/PlayGuard.ets`：播放页 `bind/unbind` 停止回调，`EntryAbility.onBackground/onDestroy` 里 `stopAll()` 兜底 |

关键代码形态：

```typescript
// 页面销毁标志：所有异步链路回来都要看
private closed: boolean = false;

// 直播：hide 即释放，回前台重连；点播：pause 保进度
onPageHide(): void {
  this.leaving = true;
  if (this.isLive) { this.reopenOnShow = true; this.releasePlayer(); return; }
  this.pausePlayback();
}

// await 之后再判一次
const p: media.AVPlayer = await media.createAVPlayer();
if (this.closed) { p.release(); return; }
this.player = p;
```

> 恢复播放时别急着清 `reopenOnShow`：切后台回来 `XComponent` 的 surface 可能被系统重建，
> `surfaceId` 会短暂为空，此时 `initPlayer()` 直接返回。要等 surface 就绪（`resumeAfterHide`
> 里 400ms × 25 次轮询）再建，否则 `reopenOnShow` 一清就再没人触发重建，画面永远黑着。

验证判据（`hilog | grep BOXN`）：返回 / 回桌面后必须看到 `onPageHide live=y` → `state=released`，
之后 **不再出现** `state=prepared` / `state=playing`。

## 四、定时抓取（每 6 小时）

三个动作打包在一轮里跑：

| 动作 | 说明 |
|---|---|
| 刷新远程配置 | 只在用户自己填过配置地址时执行，联网刷新用户填的地址 |
| 抓各站最新影片 | 逐站请求 `ac=videolist&t=&pg=1`，每站取前 10 条，按片名+年份去重，最多留 60 条 |
| 站源存活探测 | 上一步没返回数据的站记为 dead，写进 `deadKeys` |

**为什么不用后台定时器**：鸿蒙 TV 应用没有可靠的常驻后台，后台任务要权限还会被冻结。
改成「启动 / 回前台 / 前台 30 分钟定时器」触发 + 记录 `crawlAt`，超过 6 小时才真跑。
用户感知上就是"每次打开都是新的"，且不耗电。

设置页有「立即更新」按钮，可以强制跑一轮（`Crawler.run(true)`）。

并发控制在 4：电视性能有限，开太高会互相拖慢，20 个站一轮约 40~60 秒。

## 五、站源与直播源导入（订阅）

应用包内**不内置**任何影视源（配合上架合规：影视/直播源只能由用户主动订阅导入，
不能随安装包下发）。点播站源与直播源都通过两种方式导入：

1. **订阅**（推荐）：设置页 → 订阅 → 填一个订阅链接。一份订阅 JSON 同时带点播
   站源（sites）与直播源（lives），填一次两边一起更新。默认订阅源：
   `https://s3a.abber.cn:88/public/subscribe.json`
2. **手动填**：点播在「点播配置」填 TVBox 配置地址；直播在「直播源」填 m3u / txt 地址。

订阅源清单（20 个点播站源 + 10 个直播源）**不在应用包里**，独立存于
`docs/store/sites.json`（站源）与 `scripts/gen-subscription.py`（直播源），
由 `gen-subscription.py` 合成 `docs/store/subscribe.json` 后上传到 RustFS 托管。

订阅成功后，站源/直播源写入本地缓存（preferences），离线也能用；想换源重新订阅
或手动填即可。首次进入直播页若已订阅会自动选用订阅下发的第一个直播源。

## 六、一次性签名（只能人工点，约 1 分钟）

鸿蒙**拒装一切未签名 HAP**，调试描述文件必须由华为账号签发并绑定包名 + 设备 UDID。
换包名就要重新签一次，无法复用别的项目的 `.p7b`（实测过，描述文件里明文写着
`"bundle-name":"com.hong.tv"`，包名不匹配直接拒绝）。

所以第一次要在 IDE 里点一次：

1. DevEco Studio 打开 `TVBoxTV` 目录，等右下角 **Sync 完全走完**
2. 右上角设备下拉确认是目标设备（当前 `192.168.1.207:33609`）
3. 点 **▶ Run**（⇧F10）
4. 弹出「Automatically generate signature」→ **OK** → 登录华为账号

**成功判据**：`build-profile.json5` 里 `"signingConfigs": []` 变成带 `"profile": "...p7b"` 的对象。

### 换设备了怎么办

`.p7b` 里的 `device-ids` 是**设备白名单**，换一台机器装必然 `9568423`。处理：

1. **先备份旧凭证**（`~/.ohos/config/*.p7b`），否则重新生成后旧设备就装不了了
2. DevEco 里连上新设备 → **File → Project Structure → Project → Signing Configs**
3. 勾选 **Automatically generate signature** → OK
4. 新 `.p7b` 会包含新设备 UDID，重新 `./scripts/build.sh` 即可

> **⚠️ 最大的坑：`build-profile.json5` 里已有 `signingConfigs` 时，DevEco 不会重新签发。**
>
> 实测：直接点 ▶ Run，IDE 拿旧凭证打包安装，立刻报 `9568423`，**根本不弹**
> 「Automatically generate signature」。因为 IDE 认为签名配置已经就绪。
>
> 正确做法：先把 `"signingConfigs": []` 清空（`products[].signingConfig` 一并去掉），
> 再点 Run —— 这时才强制走重新签发。签完 DevEco 会把 `signingConfigs` 自动填回来，
> 但**不会写 `products[].signingConfig` 这条引用**，必须手动补 `"signingConfig": "default"`，
> 否则 warn `No signingConfig found for product default` 并产出未签名包。

整套流程可以用脚本跑（它会检测凭证是否覆盖当前设备，没有就打开 IDE 并等你按 Run，
签完自动编译装机）：

```bash
./scripts/sign-auto.sh              # 默认等 15 分钟
./scripts/sign-auto.sh --wait 180   # 自定义等待秒数
```

查当前凭证里到底白名单了哪些机器：

```bash
python3 - <<'PY'
import re
p="/Users/你的用户名/.ohos/config/xxx.p7b"
d=open(p,'rb').read()
s=re.search(rb'\{[\s\S]{200,}\}', d).group(0).decode('utf-8','ignore')
for k in ['bundle-name','device-ids','not-after']:
    m=re.search(r'"%s"\s*:\s*(\[[^\]]*\]|"[^"]*"|\d+)'%k, s)
    if m: print(k,'=',m.group(1))
PY
```

> 顺带记一笔：这次重新签发后凭证文件名从 `default_ZspaceTV_*` 变成
> `default_TVBoxTV_*`（IDE 用工程名生成），**旧的 `.cer/.p12/.p7b` 不会再被使用**，
> 但新凭证里 `bundle-name` 仍是 `com.hong.tv`，包名没变。

> `products[].signingConfig` 我已经预置成 `"default"`。上次做 ZspaceTV 时踩过这个坑：
> DevEco 只写 `signingConfigs` 不写引用，导致 `WARN No signingConfig found for product default`、
> 只产出未签名包。这次提前补上，点完就能直接用。

2. 首页 → **设置** → 填配置地址 → **导入**

## 九、排错对照表

| 现象 | 原因 | 处理 |
|---|---|---|
| `code:9568320 error: no signature file` | 没签名 | 走第 2 节 |
| `code:9568257 fail to verify pkcs7` | 用了 OpenHarmony 自签证书 | 只能用华为签发的 `.p7b`，无本地绕过 |
| 装的包能启动但立刻闪退 | 设备类型不匹配 | `module.json5` 的 `deviceTypes` 必须含 `"tv"` |
| 分类一直转圈 | 站源域名失效/被墙 | 设置里关掉该站，换一个 |
| 列表有卡片但没图没名 | 站源返回 CDATA 格式异常 | 换站源（本项目已处理 CDATA，见可行性分析） |
| 所有站源都空 | 配置本身过期 | 换一份配置地址 |
| 播放报 `5400102` / 有声音没画面 | `surfaceId` 在 idle 状态赋值了，鸿蒙只允许在 `initialized` 设 | 见下方「surfaceId 时序」 |
| 播放黑屏但有声音 | 视频编码系统不支持 | 详情页换「线路」（选带 `m3u8` 的那条） |
| 播放提示「未解析」 | 该地址需要专用解析器 | 换线路；或换 `parses` 更全的配置 |
| 遥控器焦点乱跳 | 页面元素没设 focusable | 报给我，这是 UI 层要修的 |
| `need connect-key? please confirm a device` | 多个 hdc server 抢端口，或 install 没带 `-t` | `hdc kill && hdc start`，然后 `hdc -t <IP:5555> install -r x.hap` |
| `hdc tconn` 卡住不返回 | 设备已连接时重复 tconn 会挂 | 加超时：`perl -e 'alarm 12; exec @ARGV' hdc tconn ...` |
| 直播某台黑屏十几秒才换台 | 1.0.x 及以前的版本把直播地址也送进影视解析流程 | 已修：直播走 `pickPlayableLive()`，开播前 2.5 s 探活 |
| 直播一直卡「正在连接频道…」 | 该分组的台大多失效 | 换分组；或设置页点「测速排行」，选「可播」数高的源 |
| 设置页点测速后行内容错乱 | `ForEach` 的 key 里带了 index，重排后复用错位 | 已修：直播源 key 改成 `'lp_' + url` |
| 控制条一直显示「播放」且不自动收起 | ArkUI `@Builder` 按值传参不刷新，label 一直是初始字符串 | 已修：`CtlBtn(act)` 内部读 `this.playing`，不传 label |

### surfaceId 时序（5400102 的根因）

`media.AVPlayer` 的状态机对 `surfaceId` 的赋值时机有硬要求：

```ts
// ❌ 错：idle 状态设 surfaceId → 5400102
//    Operate Not Permit: the attribute(SurfaceID) can only be set in the initialized state
p.surfaceId = sid;
await p.setMediaSource(src);

// ✅ 对：先给数据源，等进 initialized 再挂 surface
p.on('stateChange', (state) => {
  if (state === 'initialized') {
    p.surfaceId = sid;
    p.prepare();
  } else if (state === 'prepared') {
    p.play();
  }
});
await p.setMediaSource(src);   // 这一步之后才会回调 initialized
```

顺序错了的表现很有欺骗性：**音频照常播，画面全黑**——因为只有视频通道依赖 surface。

### 采集站的双线路陷阱

很多采集源的 `vod_play_url` 长这样：

```
正片$https://hn.bfvvs.com/play/dBB8Wvnd$$$正片$https://hn.bfvvs.com/play/dBB8Wvnd/index.m3u8
```

`$$$` 前那组是**网页地址**（返回 HTML，套 hls.js 播），后一组才是真流。
如果照着第一组喂播放器，就是黑屏/无法播放。现在两处都处理了：

- `Cms.splitLines()` 给每条线路算 `direct` 标记，详情页默认落在能直接播的那条，
  不能直接播的线路名后面标 `·需解析`
- `Player.fixPlayable()` 兜底：地址最后一段没有扩展名时，自动补 `/index.m3u8`，
  且先用一次 HTTP 探测确认返回头是 `#EXTM3U` 才用，没命中再走解析器

### 直播为什么不能走影视解析

直播地址本身就是**正在播的流**，影视那套流程对它全是负作用：

| 影视逻辑 | 对直播的后果 |
|---|---|
| `fixPlayable()` 补 `/index.m3u8` | `.../channel/cctv17?streamid=x` 被砍掉 query 再拼后缀，地址直接废掉 |
| `Resolver.resolve()` 轮询 8 个解析器 | 每个 2 次尝试 × 6 s，最坏 96 s 卡在「正在解析播放地址…」 |
| 用 `p.duration` 画进度条 | 直播 `duration = -1`，进度条恒为 00:00，还可能触发「播完自动下一集」 |

所以 `Player` 里按 `p.from === 'live'` 分流到 `pickPlayableLive()`：

```
主线路探活（Http.peek，带 Range 只读首包，2.5 s 超时）
  ├─ 通 → 直接 setMediaSource
  └─ 不通 → 同名备用线路（源里一个 CCTV1 常有三四条）
        └─ 全不通 → Playlist.step(1) 跳下一个台，最多 4 个 / 共 7 次探测
```

探活判据（`Live.probe`，设置页测速复用同一份）：

- 返回体含 `#EXTM3U` / `#EXTINF` → 活
- 返回体是 `<!doctype` / `<html` / `<body>` 开头，或含 `error_account`、`pirated`
  → 死（源站失效后常 302 到一张错误页或「版权下架」视频）
- 抛异常（连不上 / 超时）→ 死
- 其它（TS 分片之类的二进制）→ 交给播放器判定
